# Керування playground і модель

`boids-2d-v13` використовує одну необмежену 2D-сцену з незалежними групами, кількома нерухомими прямокутними перешкодами, полями вітру/шуму та збереженими ламаними коридорами. Одиниці — метри, секунди й метри за секунду. Це інтерпретація моделі, а не калібрування певного літального апарата. Попередній контролер коптерів збережений у гілці `codex/copter-experiment`.

## Групи й команди

Переглядач починає з порожньої сцени на паузі. У **Group** задайте кількість, seed і радіус появи, натисніть **Add [A]** та клацніть центр. Нові групи починають як Free Boids із положеннями та напрямками за seed. Декілька груп можна створювати й під час руху. Prev/Next або клацання агента вибирають групу, для якої діють подальші команди; її агентів виділяє обводка. На паузі **Delete group** видаляє вибрану групу та її агентів; номери наступних груп та агентів зменшуються. **Flight** і **Swarm** редагують профіль на паузі через **Apply profile**. `dt` належить сцені: оберіть його до першої групи або створіть нову сцену.

Для кожної напрямленої пари груп React вмикає соціальні правила й уникнення; Avoid — лише уникнення; Ignore — вимикає сприйняття й реакцію. Власна група завжди React. Фізичний контакт виводить з роботи обох незалежно від політик. Однакові профілі мають однаковий колір, тому групи розрізняють ID. Хеш профілю — FNV-1a64 з префіксом `boids-profile-v2` та впорядкованими little-endian f64 полями поведінки `Config::profile_hash`; `dt`, seed, поява, команда й політика виключені, знаки нуля нормалізовані. Можливі збіги хешу чи RGB; alpha дорівнює 255.

Команди вибраної групи:

- **Fly [V]**: протягніть стрілку від початку до кінцевої області. Початок позначає напрямок, а не обов'язкову точку.
- **Gather [G]**: намалюйте м'який круг або клацніть для Target radius. Агенти шукають доступні місця; форма рою довільна, а позиції можуть виходити за круг.
- **Follow [L]**: утримуйте кнопку над полем для оновлення цілі; після відпускання діє остання ціль.
- **Spread [B]**: клацніть для Neighbor gap або виміряйте перетягуванням. Допустимо `2.6 * body_radius <= gap <= neighbor_radius`. Тиск дистанціювання дають лише React-сусіди; руху до периметра немає.
- **Hover** зупиняє групу; **Free Boids** повертає вільний рух.
- **Route [P]**: клацайте вершини, задайте повну Route width та натисніть Enter або **Save / assign** у Swarm. Backspace прибирає вершину; Esc скасовує чернетку. Шлях можна зберегти без вибраної групи та призначити пізніше через **Assign path**. Збережений шлях не зникає від зміни активної команди.

Після жесту інструмент повертається до Inspect, команда продовжує діяти. Команди можна задавати на паузі та просувати модель через Run або Step. Arrived-агенти живі, можуть зіткнутися та реагують на нові команди. Загиблі залишаються маркерами й більше не заважають іншим.

Круглий контур кожного живого агента показує фізичний радіус зіткнення в масштабі поля. Значок напрямку має сталий розмір на екрані, щоб залишатися помітним. Виберіть агента, щоб побачити його радіус у метрах; збільште масштаб, якщо контур занадто малий.

## Об'єкти

Для **Rectangle [O]** протягніть горизонтальну ширину й відпустіть, клацніть висоту, поверніть і клацніть для підтвердження. Повторіть для інших перешкод. У Inspect наявний прямокутник можна вибрати, змінити через поля або повернути круглою ручкою. Редагування атомарне: кінцева позиція не повинна торкатися живого агента чи активної цілі. Проміжні положення під час повороту не моделюються. **Clear objects** прибирає всі прямокутники й поля.

Вітер і шум додаються незалежно. Клацніть для введених розмірів або потягніть від центра, потім поверніть і клацніть. Width і length задаються в метрах, швидкість — м/с, sigma шуму — метри; кути в UI/CLI — градуси, у Rust API — радіани. Inspect дозволяє редагувати чи повертати поля. Alt-клацання перебирає об'єкти без вибору агентів. Швидкості вітру, що перекриваються, додаються. Шум змінює спостережувані позиції; фізичні контакти та належність полям використовують істинні координати.

Restart зберігає підтверджену сцену, шляхи, поточні профілі й політики та відтворює кожну групу з її початкового центру й seed. Групи, додані в різний час на спільну ділянку, можуть не вміститися одночасно; тоді перезапуск відхиляється атомарно. Групи з явними агентами не мають seed для такого перезапуску. Програвача записів поки немає.

## Пресети сцени

Вкладка **Preset** зберігає перешкоди, поля вітру/шуму та збережені шляхи без груп, профілів, часу симуляції чи станів агентів. Введіть назву файлу та натисніть **Save new**; наявний файл не перезаписується. Для нової версії оберіть іншу назву. Непідтверджені контури й чернетки шляхів не зберігаються. Відносний шлях обчислюється від робочої теки програми; абсолютний шлях також підтримується.

Поставте симуляцію на паузу й натисніть **Load**, щоб замінити оточення та бібліотеку збережених шляхів. Наявні групи, профілі, стани, вибрана група, активні команди та маршрути залишаються. Після успіху вибір збереженого шляху та чернетки редагування очищаються. Нова перешкода, що торкається живого агента, центра активного збору чи точки активного маршруту, відхиляє все завантаження зі збереженням попередньої сцени та журналу. Один пресет можна повторно застосовувати до різних груп і параметрів. Завантаження також можливе після Stop.

UTF-8 файл має версіонований рядковий формат, окремий від JSONL. Заголовок — `SWARM_SCENE_V1`. Кожен наступний непорожній рядок має вигляд `obstacle x y width length angle`, `wind x y width length angle vx vy speed`, `noise x y width length angle sigma` або `path radius x1 y1 ...`. Кути — радіани, довжини — метри, швидкість вітру — м/с. Помилкові записи, непідтримані версії та некоректні значення відхиляються. Не редагуйте файл одночасно із завантаженням.

У CLI `--scene PATH` завантажує той самий пресет до додавання перешкод і полів з аргументів та до появи груп. Приклад: `cargo run --release --bin simulation -- --scene scene.swarm --group 0 0 10 2 42 boids --speed 2 --steps 200`. Збережені шляхи доступні у виході, але не стають автоматично командами груп. Подія `paths_replaced` у JSON фіксує заміну бібліотеки шляхів.

## Ядро моделі

Для рухомого Free Boids обчислюються: вектор відштовхування від сусідів у радіусі розділення, середній напрямок сусідів та вектор до видимих React-сусідів. Кожен ненульовий вектор нормалізується, множиться на вагу правила та додається. Команда напрямку додає власний зважений вектор. `turn_response` змішує результат із попереднім напрямком на кожному кроці; підсумок нормалізується до повітряної швидкості. Коефіцієнт заданий на крок, тому зміна `dt` змінює швидкість повороту. Розділення враховує React та Avoid, вирівнювання/згуртування — лише React. Фізичні сили, маса, прискорення й jerk не моделюються.

Найближча поверхня прямокутника порівнюється з власним радіусом огляду агента. Із видимих перешкод, що перетинають намічений шлях, найближча задає напрямок обходу. Вага від 0 до 1 змішує попередній напрямок із обходом; понад 1 ефект насичується. Фізичні контакти діють навіть за нульової ваги. Для керованих команд локальна перевірка можливих рухів враховує видимих сусідів і стіни й може змінити напрямок або швидкість. Обмежений огляд та спрощене керування не гарантують безпеки.

Gather і кінцеве паркування маршруту шукають локальні вільні місця. Для області радіуса `R` та `N` живих агентів бажана відстань: `max(separation_radius, 2.6 * body_radius, min(0.8 * R * sqrt(pi/N), 0.9 * view_radius))`, з додатковим запасом для більшого тіла іншої групи. Для Gather агент поза областю прямує до її центру, а всередині може залишитися на вільному місці. Зайняті місця та шлях через припаркованих агентів отримують штрафи. Тимчасова ціль Gather зберігається, поки не зайнята, очищається новою командою й оновлюється за блокування. Це не глобальний оптимізатор розміщення.

Прогрес маршруту окремий для кожного агента. Коридор — смуги відрізків із круглими стиками й кінцями; внутрішній radius — половина видимої ширини. Centering наближає ціль до осі; cohesion може сповільнювати передніх відносно видимих React-сусідів. Під час обходу чи через вітер агент може вийти за смугу; твердих меж і фіксованих місць немає.

Керовані Gather/Spread/Route використовують ті самі три правила та локальні цілі. Запропоновані швидкості проходять до трьох детермінованих перевірок швидких контактів із локально видимими сусідами; за можливості обирається інший напрямок або швидкість. Групи Ignore для цього планування невидимі. Це розширення класичного Free Boids, а не гарантія уникнення у всіх конфігураціях. Миттєві зупинки, повороти й прибуття — спрощені правила, а не динаміка коптера.

Вітер додається до земної швидкості на початку кроку: `ground_velocity = air_velocity + wind`, `position_next = position + ground_velocity * dt`. Керований рух може компенсувати вітер у межах повітряної швидкості. Шум — гаусова похибка позиції з нульовим середнім по осях; визначається seed групи, локальним індексом агента, кроком та полем. Читання не витрачає випадковість. Фізичні контакти й належність полям використовують істинні координати; лінії сусідів в UI можуть відрізнятися від шумного сприйняття. Невдалий чисельний крок зберігає попередні стан і час.

## CLI та дані

```powershell
cargo run --release --bin simulation -- --steps 400 --rectangle 4 0 2 3 --obstacle-angle 30 --rectangle 8 2 1 2 --obstacle-angle -15 --group -3 0 10 1 42 boids --gather 12 0 1 --group -3 5 8 1 99 boids --interaction 0 1 avoid --interaction 1 0 ignore --trace run-001.jsonl
```

`--rectangle X Y WIDTH_X HEIGHT_Y` і `--square X Y SIDE` можна повторювати. `--obstacle-angle DEG` застосовується до попередньої фігури; його також можна задати до першої. Поля `--wind-rect X Y WIDTH LENGTH ANGLE_DEG SPEED` та `--noise-rect X Y WIDTH LENGTH ANGLE_DEG SIGMA` повторювані. Rust використовує радіани й `Rectangle::new(center, width, length)`, де length спрямована вздовж нульового кута; X/Y розміри перешкоди CLI відповідають length/width до повороту.

`--group X Y COUNT RADIUS SEED boids` починає групу. Наступні параметри профілю/команди/маршруту стосуються неї до наступної групи; профільні значення успадковуються, команда очищається. `dt` спільний. Без явних груп працює звичний `--agents`; `--empty` створює порожню сцену. Повний список — у `--help`.

Stdout — один JSON v13. `--trace` створює новий файл із початковим станом та кожним завершеним кроком, не перезаписуючи наявні файли. `units` описує одиниці SI; `groups` містить ID, seed, профілі, команди, кольори та політики; `paths` — збережені шляхи; `agents` — `group_id`, істинні/виміряні координати, земну/повітряну/вітрову швидкість, стан та індекс вершини; `scene.rectangles` — усі перешкоди, `scene.rectangle` дублює першу для сумісності. `events` містить sequence, step і time змін сцени, груп, профілів, команд та станів. Подія з'являється в JSONL один раз; підсумок stdout містить усю історію. Події станів мають точність кроку. Довгі записи займають пам'ять/диск, а збій I/O може залишити неповний останній рядок.

## Формат експорту v13

JSON має `schema_version: 2`. `uid` агента та групи не змінюються при видаленні інших груп у межах одного запуску; після Restart починається новий запуск. `id` і `group_id` залишаються поточними індексами. Події містять `agent_uids` та `group_uids`; `agent_contact` і `obstacle_contact` включають час контакту всередині кроку. Для одночасних контактів може бути кілька подій. Параметри груп — у `groups`, старі спільні поля — у `legacy`. `event_scope` відрізняє повну історію підсумку від приросту JSONL. Опція `--trace-every N` записує початковий та кінцевий стан і кожний N-й крок, зберігаючи всі проміжні події. `task_observation` показує відстань до кінцевої цілі та належність до бажаної області; `arrived` не означає гарантованого успіху.
