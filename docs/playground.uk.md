# Сцени playground

Модель `boids-2d-v11`: одна необмежена 2D-сцена, незалежні групи, нерухомий прямокутник, поля вітру/шуму та широкі ламані коридори. CLI та вікно використовують спільне ядро з фіксованим кроком. Величини демонстраційні, без калібрування справжнього коптера.

## Побудова сцени

Переглядач відкриває порожнє поле на паузі. У **Group** задайте count/seed/spawn radius, виберіть **New: Copters / Boids** (типово Boids), натисніть **Add [A]** і клацніть центр появи. Коптери починають зі спокою; Free Boids — зі сталої швидкості та випадкових напрямків за seed. Додавати групи можна під час руху. ID агентів і груп стабільні; невдале розміщення не змінює сцену. Кількість агентів обмежена доступними ресурсами та можливістю розміщення.

Групу обирають через Prev/Next або вибір її агента. **Flight** та **Swarm** показують її профіль. **Apply profile** працює лише на паузі: положення та загиблі зберігаються, швидкості обмежуються новими межами, керувальне прискорення обнуляється. Це явне редагування поза звичайним обмеженням jerk. Некоректні зміни відхиляються. Count/seed/spawn radius стосуються лише нових груп.

Усі групи мають спільний крок сцени `dt`. Оберіть його до першої групи на кроці нуль або почніть **New scene** на паузі/після зупинки. Решта параметрів руху належать групам.

Для кожної напрямленої пари оберіть **To group** та політику:

| Політика | Сприйняття іншої групи |
| --- | --- |
| React | Соціальне вирівнювання/згуртування та дистанціювання/уникнення |
| Avoid | Лише уникнення; без соціальних правил та тиску дистанції Spread |
| Ignore | Немає сприйняття чи планованої реакції |

Редагування політик — на паузі. Напрямки незалежні; типово React. Власна група завжди React. **Фізичний контакт за будь-якої політики виводить з роботи обох агентів, навіть якщо вони ігнорують один одного.** Нульова вага відповідного правила може вимкнути планування уникнення.

Колір — підказка про параметри, а не ідентифікатор групи. Однакові профілі мають однаковий RGB незалежно від seed, кількості, положення, поточної команди та політик. Alpha завжди 255. Групи з однаковим профілем розрізняйте за ID. Хеш — FNV-1a64 від `boids-profile-v1` та впорядкованих little-endian f64 полів `Config::profile_hash`; спільний `dt` виключений, знаки нуля нормалізовані. Це не криптографічний хеш; збіги хешів і кольорів можливі.

## Команди та шляхи

Команда стосується вибраної групи. Після завершення жесту інструмент повертається в **Inspect**, а команда групи залишається активною.

- **Fly [V]**: стрілка до цільової області. Початок — орієнтир напрямку, а не обов'язкова точка для всіх.
- **Gather [G]**: намалюйте м'який круг або клацніть для Target radius. Агенти займають доступні місця поблизу, без примусової круглої форми. Агент у вільній частині області може залишитися там. Щільний рій може виходити за круг.
- **Follow [L]**: утримуйте ліву кнопку для оновлення цілі. Відпускання залишає останню ціль.
- **Spread [B]**: клацніть для Neighbor gap або виміряйте перетягуванням. Допустимий діапазон: `2.6 * body_radius <= gap <= neighbor_radius`. Дистанціювання задають лише видимі React-сусіди; Avoid-сусіди беруть участь у прогнозованому уникненні. Ізольовані агенти лишаються на місці. Це не рух до периметра й не гарантія рівномірного пакування.
- **Hover** негайно запитує зупинку; **Free Boids** вмикає класичне керування напрямком зі сталою швидкістю. Діють лише на вибрану групу.
- **Route [P]** у Scene: клацайте вершини, задайте Route width, потім Enter або **Save / assign** у Swarm. Backspace прибирає вершину, Esc скасовує чернетку. Шлях можна зберегти без групи. Якщо група вибрана, виконується також спроба призначення. Оберіть збережений Path та **Assign path** для іншої групи. Нова команда очищає активний маршрут, але збережений шлях залишається.

Круг задає приблизну щільність через локальний пошук вільного місця, без фіксованих слотів. За щільності чи перекриття огляду можливі черги та незавершена стабілізація. Arrived-агенти живі, фізично присутні й приймають наступні команди. Їхній корпус зберігає колір групи, синє кільце означає очікування. Загиблі — червоні хрестики, які більше не перешкоджають іншим.

## Об'єкти

Прямокутник будується у три етапи: протягніть горизонтальну ширину й відпустіть, клацніть висоту, поверніть попередній контур і клацніть для підтвердження. Розміри незалежні. Другий прямокутник замінює перший; кілька твердих перешкод поки не підтримуються.

Вітер і шум мають незалежні Width/Length: клацніть для введених розмірів або протягніть від центра для їх зміни; відпустіть, поверніть контур та клацніть. Wind speed і Noise sigma не залежать від розмірів. Inspect дозволяє обрати наявний об'єкт, повернути круглою ручкою або задати точні властивості через **Apply object**. Alt-клацання пропускає агентів під час вибору об'єктів. **Clear objects** прибирає тверду перешкоду й поля.

Зміни діють одразу на межі кадру, зокрема на паузі. Кінцеве положення перешкоди, яке торкається живого агента чи активної цілі, відхиляється. Поворот/масштабування — атомарне редагування; проміжні положення не симулюються. Поля не тверді.

**Restart** відтворює групи за початковими умовами появи з поточними профілями, командами, маршрутами й політиками, зберігаючи об'єкти та шляхи. Час і журнал подій починаються заново. Перезапуск може не вдатися, якщо групи, додані в різний час, мали спільну область появи або геометрія тепер заважає розміщенню. Попередній світ зберігається. Групи з явними агентами `Simulation::new` мають `seeded: false` та не підтримують такий перезапуск. Завантажувача файлів сцени та програвача записів поки немає.

## Сприйняття стін та коридори

Кожна група має власний круговий `neighbor_radius`. Стіна сприймається, коли в радіус потрапляє **найближча поверхня**, а не центр. Після цього контролер знає повну геометрію нерухомого прямокутника. Політика Ignore між групами не приховує стіни. `obstacle_weight = 0` вимикає планування обходу, але контакти залишаються.

Коптери шукають локальний обхід графом видимості навколо тіла із зазором `obstacle_clearance` та прогнозують контакти тим самим приводом з обмеженням jerk. Усередині планувального зазору зберігається дотична ціль, якщо прямий шлях не перетинає фізичне тіло. Free Boids використовує простіший обхід напрямком; направляюча проходить за видиму стіну, щоб ціль усередині товстої перешкоди не поверталася на ближню грань без повороту агента.

Тіла-диски мають точні контакти вздовж усього кроку з гранями та округленими кутами, також за повороту прямокутника. Контакт виводить агента з роботи. Обмежений огляд, гальмування, шум, великий крок та локальні мінімуми все ще можуть спричиняти зіткнення чи застрягання. Гарантії безколізійного руху немає.

Шлях — широкий м'який коридор: смуги відрізків з округлими стиками та кінцями. Route width — повна ширина; `Route::new(points, radius)` використовує півширину. Агенти входять у доступній бічній позиції та проходять вершини незалежно. `route_centering` повертає до осі; нуль дозволяє вільне бічне положення. `route_cohesion` сповільнює передніх для видимих React-сусідів позаду. Правило призупиняється біля видимої стіни та під час кінцевого паркування. Avoid та Ignore не притягують групу соціально. Фіксованих формацій чи загального очікування немає. Вітер та обхід можуть виносити за смугу; агенти намагаються повернутися. Вершини всередині фізичної перешкоди відхиляються, але сама смуга може її перетинати.

## Вітер та вимірювання

Вітер — кінематичне поле швидкості, а не аеродинамічна сила. Перекриті швидкості додаються. На початку кроку вимірюється `w(p)`; далі `v_air_next = v_air + a_next * dt`, `v_ground = v_air_next + w`, `p_next = p + v_ground * dt`. Межі швидкості/прискорення/гальмування/jerk стосуються керованого повітряного руху. Земна швидкість може бути більшою; сильний вітер може зірвати зависання. Різкі межі поля дають дискретні зміни; перевіряйте їх зі зменшеним `dt`.

Шум — незалежна гаусова похибка положення з нульовим середнім по кожній осі. Контролер спостерігає себе й сусідів через неї. Фізичні контакти, належність полям і збережені координати використовують істинну геометрію. Швидкість і вітер вимірюються ідеально. Вибірки залежать від seed групи, локального індексу агента, кроку та індексу поля. Читання чи експорт не витрачають випадковість. Явні групи мають seed вимірювання нуль. Лінії сусідів показують істинні координати з фільтром політик; шумне планування може відрізнятися.

## CLI та аналіз

```powershell
cargo run --release --bin simulation -- --empty --steps 0
cargo run --release --bin simulation -- --steps 400 --rectangle 4 0 2 3 --obstacle-angle 30 --group -3 0 10 1 42 copters --speed 1 --gather 7 0 1 --group -3 5 8 1 99 boids --speed 0.8 --interaction 0 1 avoid --interaction 1 0 ignore --trace run-001.jsonl
cargo run --release --bin simulation -- --group -3 0 10 1 42 copters --waypoint -3 0 --waypoint 7 0 --waypoint 7 3 --route-width 2 --steps 400
```

Повторюваний `--group X Y COUNT RADIUS SEED copters|boids` починає групу. Наступні параметри профілю/команди/маршруту стосуються її до наступного оголошення. Значення профілю успадковуються, команда й маршрут очищаються. Усі групи повинні мати однаковий `dt`. `--agents` не поєднується з явними групами. Без груп старий CLI типово створює десять Free Boids; `--empty` не створює жодного. Для групи дозволено одну команду або маршрут; маршрут замінює початковий режим.

`--rectangle X Y WIDTH_X HEIGHT_Y` задає тверду перешкоду; `--square X Y SIDE` — рівні розміри. `--obstacle-angle` / `--square-angle` використовують градуси. Повторювані поля: `--wind-rect X Y WIDTH LENGTH ANGLE_DEG SPEED` та `--noise-rect X Y WIDTH LENGTH ANGLE_DEG SIGMA`. Їхня length спрямована вздовж кута, width — впоперек. Rust `Rectangle::new(center, width, length)` використовує цю саму домовленість; розміри CLI-перешкоди X/Y відповідають length/width за нульового повороту. Кути Rust — радіани. Старі квадратні поля також підтримуються. Решта параметрів — у `--help`.

Stdout містить один JSON-підсумок. `--trace` створює новий JSONL: початковий знімок та кожний завершений крок. Наявні файли ніколи не перезаписуються. Основні поля v11: `groups[]` (профіль, поява, команда, політики, хеш, RGBA), `paths[]`, `agents[].group_id`, `scene.rectangle` (center, width, height, angle_degrees), `events[]`. Верхні config/command дублюють нульову групу для сумісності; seed/spawn_radius — старі вхідні параметри. Для кількох груп читайте spawn кожної групи. `scene.rectangle` навмисно замінює старе `scene.square`.

Журнал містить додавання груп, зміни профілю/команди/політики, редагування сцени, збереження шляхів і переходи станів із sequence, step та модельним часом. У JSONL кожна подія записується один раз; підсумок stdout містить усю історію. Час подій контакту округлений до кінця розрахованого кроку, хоча положення контакту знаходиться всередині кроку. Це не точний потік часу підкроків і не програвач. Історія займає RAM, довгі записи — диск. Помилка запису може залишити неповний останній рядок.

Знімок агента містить ID, group_id, істинне/виміряне положення, земну/повітряну/вітрову швидкість, керувальне прискорення, waypoint_index та стан moving/arrived/terminated. Невдалий чисельний крок зберігає попередній стан, час та історію. Повторюваність потребує тієї самої моделі, lockfile, входів і чисельного середовища; побітова рівність між платформами не обіцяється.
