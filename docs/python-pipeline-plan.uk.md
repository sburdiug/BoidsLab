Повне технічне завдання для моделі-виконавця: [Python implementation handoff](python-pipeline-plan.md). Висновки перевірки архітектури: [Architecture review](architecture-review-2026-11-10.md).

## Мета першої версії

Отримати відтворюваний ланцюжок: опис експерименту → запуск готового Rust CLI → перевірка JSON/JSONL → метрики → CSV, PNG та Markdown-звіт. Фізика залишається в Rust. Python запускає досліди й аналізує дані.

Перший результат — контрольні тести, невелика серія дослідів і зрозумілі графіки. Без вебдашборду, бази даних, оптимізатора параметрів і переписування симулятора.

## Послідовність робіт

1. Зчитування й перевірка формату; тести метрик на малих прикладах із відомими відповідями.
2. Запуск процесу з таймаутом, збереження сирих файлів, параметрів, версій та хешів. Невдалий запуск залишається у звіті.
3. Контрольні запуски: порожня сцена, рівномірний рух одного агента, Hold, прибуття до центра, повторюваність за однакового seed.
4. Перші 18 дослідів: вага alignment 0/1/3 для трьох seed; збір без перешкоди, збір із прямокутником і рух ламаним коридором — також для трьох seed.
5. Графіки траєкторій, часток станів, узгодженості напрямків, розміру рою, швидкості й відхилення від цілі або маршруту. Таблиці результатів і короткий звіт.

## Що вимірюємо

- Частки рухомих, прибулих та загиблих від початкової кількості агентів групи.
- Центр рою, середньоквадратичний розкид, узгодженість напрямків і середню швидкість живих агентів.
- Відстані між агентами з урахуванням фізичних радіусів.
- Відстань до цілі, частку всередині м'якої області, відхилення від маршруту.
- Час до 90% прибулих; якщо поріг не досягнуто, результат невизначений, а не час завершення досліду.

Метрики розраховуються окремо для груп. Немає живих агентів — немає вигаданого нульового центру чи узгодженості. Повторення за різними seed — це повторні досліди; сусідні кадри не є незалежними повтореннями.

## Важливі обмеження архітектури

- Номери груп та агентів змінюються після видалення. Перший аналізатор працює лише зі сталим складом груп у CLI.
- Експорт показує загибель агентів, але не причину й точну пару зіткнення. Не можна називати половину кількості загиблих кількістю зіткнень.
- `arrived` — стан, а не універсальний доказ успіху: Hold теж створює цей стан, а область збору м'яка.
- Параметри й seed треба читати з кожної групи. Загальні поля можуть описувати лише першу групу або старі CLI-значення.
- Події підсумкового JSON повторюють історію JSONL. Їх не можна рахувати двічі.
- Пресет зберігає оточення, а не повний стан експерименту. Збережений шлях самостійно не призначається групі.
- Час процесу включає створення сцени та запис даних; він не дорівнює часу ядра чи FPS.

Архітектура вже придатна для цього малого пайплайну. Твердження про стабільні ID у карті модулів виправлено; поведінку Rust під час цього ревью не змінено. Поточні 109 Rust-тестів пройшли. Продуктивність великих сцен і нові графіки ще не перевірялися.

## Критерій готовності

Інша модель реалізує англійське технічне завдання поетапно. Із чистої копії репозиторію за інструкцією можна запустити контрольні тести, всі заплановані досліди та отримати CSV, PNG і звіт з усіма помилками та обмеженнями. Великі серії, вітер/шум, взаємодія кількох груп і пошук параметрів — наступний етап після перевірки першого результату.
