# Симуляція рою

Двовимірна модель із фіксованим кроком: класичні Boids для порівняння та незалежно керовані коптери. Версія — `boids-2d-v11`. Площина необмежена; числові значення демонстраційні й не калібровані під справжній БПЛА.

## Запуск

```powershell
cargo run --bin simulation -- --agents 10 --steps 600 --seed 42 --gather 0 0 0.05
cargo run --bin simulation -- --spread 0.8 --steps 600
cargo run --bin simulation -- --max-acceleration 1 --max-braking 2 --max-jerk 8 --gather 2 3 1 --steps 600
cargo run --bin simulation -- --help
cargo run --release --features viewer --bin viewer
```

`cargo run` запускає CLI. Він повертає один JSON-підсумок із параметрами, командою, кількістю агентів за станами, кінцевими положеннями, швидкостями та прискореннями. Помилки надходять у stderr із невдалим статусом завершення. CLI використовує заданий горизонт та окрему команду для кожної групи; бібліотека приймає нові команди між кроками. Старий режим типово створює десять агентів; `--empty` запускає порожній світ. Керовані регіональні запуски CLI починаються зі спокою, як у переглядачі. Free Boids починає рух із випадковими напрямками за seed та заданою швидкістю.

## Переглядач

Початковий стан — пауза та порожнє поле. У **Group** задайте count/seed/spawn radius, виберіть **New: Copters / Boids**, натисніть **Add [A]** та клацніть центр появи. Групи можна додавати під час руху. Вибір групи — Prev/Next або вибір її агента. Команди стосуються лише вибраної групи; після жесту інструмент повертається в Inspect, а команда лишається активною.

**Flight** і **Swarm** редагують профіль вибраної групи через **Apply profile** лише на паузі. Редагування зберігає положення та загиблих, обмежує швидкості новими межами й обнуляє керувальне прискорення. **Scene** містить прямокутну перешкоду та поля вітру/шуму. Шляхи можна зберігати без групи й призначати через **Swarm**. [Докладні правила та схема даних](docs/playground.uk.md).

Для кожної напрямленої пари груп **React** вмикає соціальні правила та уникнення, **Avoid** — лише уникнення, **Ignore** — вимикає сприйняття цієї групи. Типово React; власна група завжди React. Фізичний контакт за будь-якої політики виводить з роботи обох агентів. Колір залежить від поведінкових параметрів, а не ID, seed чи місця появи. Однакові профілі мають однаковий колір; розрізняйте групи за ID.

| Дія | Керування |
| --- | --- |
| Запуск / пауза | F5 або кнопка |
| Один точний крок і пауза | F6 або Step |
| Відтворити групи з поточними профілями та початковими умовами появи | F8 або Restart |
| Завершити запуск зі збереженням зображення | F7 або Stop; для нового запуску Restart |
| Темп 0.5x–4x | Кнопки або F3 / F4 |
| Переміщення камери | Права/середня кнопка з перетягуванням; стрілки |
| Масштаб | Колесо над полем; + / - |
| Початок координат і 100% | Reset view або F10 |
| Вибір агента | Inspect [I], клацання; F11 перебирає агентів |
| Показ сусідів | F9 |
| Скасувати вибір, редагування та жест | Esc |

- **Fly [V]**: стрілка переміщує бажану область збору; її початок не є точкою маршруту.
- **Gather [G]**: намалюйте бажаний круг від центра до краю або клацніть для використання **Target radius**.
- **Spread [B]**: задайте **Neighbor gap** і клацніть або виміряйте відстань перетягуванням. Це локальна дистанція між сусідами, без цільового круга.
- **Follow [L]**: утримуйте ліву кнопку для оновлення області збору; після відпускання остання ціль лишається активною.
- **Hover** негайно запитує зупинку; вітер сильніший за доступну повітряну швидкість може завадити зависанню. **Free Boids** повертає класичний базовий режим.

Круг — **м'який орієнтир**, а не контейнер чи обмеження місткості. Агенти у вільній частині області можуть залишатися там; новоприбулі займають доступні місця поблизу. Область задає приблизну щільність без вимоги круглої форми рою чи обходу до центра. За браку місця агенти можуть стабілізуватися поза кругом. Прибулі залишаються живими та фізично присутніми; у полях вітру/шуму вони продовжують керувати зависанням і можуть відхилятися. Під час зависання зберігається колір групи з синім кільцем, вибуття — червоним хрестиком. П'ятикутний маркер показує напрямок руху, а не орієнтацію корпуса. Інспектор розрізняє істинне й виміряне положення, земну/повітряну швидкість, вітер, керувальне прискорення та точку маршруту. Лінії й кількість сусідів враховують істинну геометрію та напрямлені політики сприйняття.

Масштаб змінюється плавно навколо центра зображення; одиниці колеса Windows нормуються. Протилежні кроки повертають масштаб, якщо не досягнуто межі. Після редагування клацніть по полю або натисніть Esc для клавіатурної навігації. Мінімальний розмір вікна — 1000 × 760. Canvas має клавіатурне керування, але не має семантики для екранних читачів.

Позиції інтерполюються між кроками фізики з частотою кадрів; лінії сусідів і вибір мишею використовують видимі положення. Фізичні стани й результати CLI від цього не змінюються. Затримка зображення — приблизно один модельний крок (`dt / playback_rate` секунд). Пауза та одиночний крок показують точні положення; маркери вибуття — точку контакту. За кадр виконується максимум вісім кроків; після восьми мілісекунд роботи керування повертається між кроками зі збереженням залишку. Один крок може перевищити бюджет. Індикатор Lag показує відставання; за постійного перевантаження модель відстає від реального часу. Інтерполяція не усуває низький FPS під навантаженням.

## Вибір місця та локальний обхід

**Немає заздалегідь призначених місць, резервування точок, спільного часу прибуття чи траєкторій побудови.** На кожному кроці рухомий агент читає попередній спільний стан і незалежно обирає тимчасову локальну ціль.

Для Gather базова ціль — найближча точка корисної області, зокрема поточне положення, якщо агент уже всередині. Пріоритет мають припарковані сусіди або ближчі до центра; за рівності — сталий індекс. Локальні кандидати включають поточну позицію та 16 точок навколо таких сусідів. Бажаний проміжок: `max(separation_radius, 2.6 * body_radius, min(0.8 * radius * sqrt(PI / alive_group_count), 0.9 * neighbor_radius))`, із додатковим запасом для більшого тіла іншої групи. Кандидати мінімізують вихід за м'яку область та невелику вартість переміщення, зі штрафом за перетин припаркованих сусідів. Цілі тимчасові й не резервуються; за блокування агент може гальмувати або чекати.

Кожна вісь запитує швидкість до тимчасової цілі з урахуванням гальмування й jerk. За наявності видимих сусідів оцінюється до 25 запитів: дванадцять напрямків із повною та половинною швидкістю і зупинка. Той самий обмежений за jerk привід прогнозується приблизно на 1.5 секунди, максимум 30 кроками. Сусіди прогнозуються з поточною сталою швидкістю; захисний радіус — `max(1.4 * (own_body_radius + other_body_radius), 0.75 * separation_radius)`. Прогнозовані контакти отримують великий штраф. За відсутності активного видимого джерела уникнення використовується лише прямий запит. Планування враховує тільки сусідів у межах `neighbor_radius`.

Це локальна евристика з обмеженою кількістю перевірок, а не оптимальний планувальник чи гарантія відсутності зіткнень. Інші агенти можуть змінити рух після прогнозу. Малий огляд, слабке гальмування, невдалі параметри або щільна група можуть спричинити контакти, черги та затори. Вибірка не перебирає всі вільні положення й не оптимізує пакування.

Перехід у `Arrived` відбувається після 0.3 модельної секунди зі швидкістю та прискоренням нижче 0.001 відповідних меж і за безпечного зазору до видимих тіл. Для Gather і кінцевого паркування на маршруті агент має бути біля бажаного круга з допуском одного радіуса тіла або біля видимого прибулого сусіда, ближчого до центра. Так припаркована група може рости за межі малого круга. Під час прибуття повітряна швидкість ідеально компенсує вибраний вітер, а керувальне прискорення обнуляється. Без вітру це попередня зупинка з нульовою швидкістю. Нова команда активує прибулих; швидкість і прискорення тих, хто вже летить, зберігаються. Вибулі ніколи не відновлюються.

## Маршрут і локальне розосередження

Маршрут має м'яке тяжіння до центра: `route_centering` типово 0.25; 0 повертає вільне бокове слідування. `route_cohesion` типово 1: передні коптери сповільнюються, якщо видимі сусіди відстають; 0 вимикає цю поведінку. Обидва параметри розміщені у **Swarm**, застосовуються через Apply profile на паузі і мають CLI-прапорці `--route-centering` / `--route-cohesion`. Незалежний прогрес маршруту й уникнення зіткнень збережено. Жорсткі квадратні, круглі, ромбічні чи трикутні формації не призначаються.

Spread задає мінімальний проміжок між центрами через `Command::Spread { spacing }` або `--spread GAP`. Агент підсумовує відштовхування від видимих сусідів, ближчих за бажану дистанцію; ізольований агент залишається на місці. Допустимо `2.6 * body_radius <= spacing <= neighbor_radius`. За спокійного стану агент може зависнути на 98% заданого проміжку та активується знову, якщо видимий сусід наблизиться. Симетричні сили можуть залишити агента біля центра, поки зовнішні агенти розходяться. Це локальна дистанція, а не рівномірне пакування чи гарантія зв'язності всієї групи.

Версія v9 навмисно замінює стару кільцеву команду `--spread X Y R`. JSON тепер містить `{"type":"spread","spacing":...}` і дві ваги маршруту в `config`. Скрипти, що очікували центр/радіус Spread, потрібно оновити.

## Рух і параметри

Стан коптера містить положення `p`, повітряну швидкість `v` та керувальне прискорення `a`. Земна швидкість — `v + wind`; наведені межі стосуються керованого руху відносно повітря. На кожному кроці:

- `|v| <= speed`;
- `|a| <= max_acceleration`, якщо `dot(v_previous, a) >= 0`, інакше `|a| <= max_braking`;
- `|a_next - a_previous| <= max_jerk * dt`.

Привід наближає прискорення до запиту в межах jerk. Консервативна оцінка майбутньої швидкості `v + a * (dt + |a| / (2 * max_jerk))` не дозволяє розганятися так, щоб прискорення не встигло зменшитися до обмеження швидкості. Пошук із обмеженою кількістю зменшень запиту знаходить допустиме прискорення. Напівнеявний крок: `v_next = v + a_next * dt`, `p_next = p + (v_next + wind) * dt`. Вітер вибирається на початку кроку; межі поля різкі в цій кінематичній моделі. Це дискретні обмеження, без роторів, орієнтації, гравітації та аеродинаміки. Крок часу впливає на чисельну похибку, але не змінює задані межі розгону, гальмування й jerk.

| Параметр | Типово | Значення |
| --- | --- | --- |
| `dt` | 0.1 | Модельні секунди за крок |
| `speed` | 1 | Максимальна повітряна швидкість; стала повітряна швидкість Boids |
| `max_acceleration` | 1 | Межа розгону, одиниць/с² |
| `max_braking` | 2 | Межа гальмування, одиниць/с² |
| `max_jerk` | 8 | Межа зміни прискорення, одиниць/с³ |
| `neighbor_radius` | 1 | Круговий огляд |
| `separation_radius` | 0.3 | Бажаний зазор коптерів та запас обходу; радіус відштовхування Boids |
| `body_radius` | 0.025 | Радіус фізичного диска; розмір маркера незалежний |
| `separation_weight` | 10 | Вага Boids; для коптерів сила штрафу уникнення насичується на 1, 0 вимикає |
| `turn_response` | 0.1 | Лише реакція напрямку базових Boids |
| `alignment_weight` / `cohesion_weight` | 1 / 3 | Лише вирівнювання/зближення базових Boids |
| `command_weight` | 1 | Множник швидкості коптера, насичення на 1; вага напрямку Boids |
| `obstacle_clearance` | 0.15 | Додатковий зазор поверхні для планування; UI: Obstacle gap |
| `obstacle_weight` | 1 | Штраф прогнозованого контакту; 0 вимикає планування обходу |

`Hold`, перехід у базовий режим і вибуття після контакту — явні стрибкоподібні зміни поза обмеженнями приводу коптера. Перехід у зависання моделює ідеальну стабілізацію біля спокою. Базові Boids для порівняння зберігають сталу швидкість: нормовані розділення, вирівнювання та зближення зважуються й змішуються з попереднім напрямком. Фізика прискорення коптера до цього режиму не застосовується.

## Контакти та повторюваність

Контакт на відстані сумі радіусів тіл обох груп спричиняє вибуття в усіх режимах. Перевіряється весь прямолінійний рух усередині кроку, навіть якщо агенти не бачили один одного. Події обробляються за часом; одночасний контакт має пріоритет над паркуванням. Вибулі лишаються маркерами та більше не заважають руху. Події з різницею до `1e-10 * min(dt, 1)` вважаються одночасними.

Невдалий чисельний крок зберігає весь попередній стан і годинник. Недопустимі або нескінченні значення повертають помилки; надзвичайні скінченні числа також можуть перевищити чисельний діапазон. Повторюваність потребує тієї самої моделі, lock-файла, історії команд і чисельного середовища; побітова однаковість між платформами не гарантується.

## Перевірки й обмеження

```powershell
cargo test --all-features --locked --offline
cargo clippy --all-targets --all-features --locked --offline -- -D warnings
cargo fmt --check
```

Перевіряються межі приводу, діагональні зміни цілі, зменшення кроку, незалежність від реакції Boids, локальне паркування біля нерухомого сусіда, вихід за м'яку область, контрольні групові сценарії, контакти, атомарні помилки, CLI, seed та плавне відтворення. Перевірки сцени також покривають контакти з квадратом, обхід, компенсацію та переважання вітру, відтворюваний шум, незалежний прогрес маршруту, збереження сцени за Restart та JSONL-запис. Калібрування реального апарата, криві сплайни, дослідницький дашборд поки відсутні. Перешкода наразі одна: нерухомий прямокутник із поворотом; [деталі сцени та схема запису](docs/playground.uk.md). Просторові сітки прискорюють пошук сусідів і контактів без обрізання огляду. Щільний локальний пошук та попарна ініціалізація залишаються витратними. Dev-збірки використовують opt-level 2. Див.
