# BoidsLab

[English version](README.md)

Двовимірна агентна симуляція з фіксованим кроком, локальною моделлю Boids, інтерактивним середовищем та CLI. Це дослідницький прототип, а не відкалібрована модель реального БПЛА. Поточна версія моделі — `boids-2d-v14`, формат експорту — JSON schema 2.

У BoidsLab можна створювати кілька груп, змінювати їхні параметри й команди, додавати прямокутні перешкоди, вітер і шум, зберігати середовище та проводити повторювані експерименти. Python-аналізатор будує графіки й звіти за результатами запусків.

## Запуск

Потрібен [Rust із Cargo](https://www.rust-lang.org/tools/install). Для аналізатора також потрібен Python 3.11 або новіший; залежності встановлюються командою нижче.

```powershell
cargo run --release --features viewer --bin viewer
cargo run --release --bin simulation -- --agents 10 --steps 600 --seed 42
cargo run --release --bin simulation -- --help
```

Переглядач відкриває порожню сцену на паузі. У **Group** задайте кількість, seed і радіус появи, виберіть **Add [A]** та клацніть поле. Додавайте кілька груп; вибір — Prev/Next або клацання агента. Команди стосуються вибраної групи. Додавати групи можна під час руху. У **Flight** і **Swarm** редагуйте профіль, призупиніть симуляцію та натисніть **Apply profile**. Крок часу спільний для сцени.

Доступні **Fly**, **Gather**, **Spread**, **Follow**, **Hover** та **Free Boids**. Після жесту інструмент повертається до Inspect, а команда залишається активною. У **Scene** прямокутник створюється трьома діями: протягнути ширину, клацнути висоту, повернути й клацнути. Прямокутників може бути кілька; кожен редагується окремо. Також є поля вітру і похибки положення. Route — широкий ламаний коридор: клацайте вершини й натисніть Enter для збереження та призначення. Шлях можна зберегти без групи й призначити пізніше. [Докладне керування та дані](docs/playground.uk.md).

У **Preset** можна зберегти оточення та збережені шляхи в новий файл і пізніше завантажити до тієї самої чи іншої сцени. Групи, їхні параметри та поточні команди не входять до пресета. Перед завантаженням поставте симуляцію на паузу; перешкода, що перетинає живого агента чи активну ціль, відхиляє завантаження цілком. Збереження не перезаписує наявний файл: оберіть іншу назву. Відносний шлях рахується від робочої теки програми; також можна ввести абсолютний шлях.

Для кожної напрямленої пари груп **React** враховує соціальну поведінку й уникнення, **Avoid** — лише уникнення, **Ignore** — вимикає сприйняття. Фізичний контакт однаково виводить з роботи обох агентів, навіть за взаємного Ignore. Однакові поведінкові профілі мають однаковий колір; групи розрізняють ID та обводка вибору. Restart відтворює групи за seed з поточними профілями й політиками, зберігаючи об'єкти та шляхи. Якщо початкові області перетинаються або заважає перешкода, перезапуск може бути відхилений зі збереженням попереднього стану.

## Модель та одиниці

Координати й відстані — **метри**, час і `dt` — **секунди**, швидкість і вітер — **метри за секунду**. Поле показує розмір комірки сітки в метрах. Один агент зі швидкістю 2 м/с проходить 2 м за одну модельну секунду; 1 м/с дорівнює 3,6 км/год. Числа демонстраційні та придатні до зміни в експериментах; самі одиниці не калібрують модель під реальний літальний апарат.

Типовий радіус агента — **0,10 м**, діаметр — **0,20 м**; інші розміри також можна задати. Видимий контур показує фізичний радіус у масштабі сцени.

У Free Boids агент враховує сусідів у круговому радіусі огляду. Розділення, вирівнювання й згуртування створюють вектори напрямку; вони нормалізуються та додаються з незалежними вагами. Команда напрямку додає власний зважений вектор. Результат змішується з попереднім напрямком через `turn_response` на кожному кроці та нормалізується до повітряної швидкості агента. За відсутності нового напрямку зберігається попередній. Це агентна модель, а не модель фізичних сил і маси. Коефіцієнт повороту заданий на крок, тому зміна `dt` без зміни коефіцієнта змінює поведінку.

Прямокутник сприймається, коли найближча поверхня потрапляє в радіус огляду. Якщо він перетинає намічений напрямок, контролер будує напрямок обходу. Вага перешкоди 0 вимикає планування, значення від 0 до 1 змішують напрямок обходу, а понад 1 мають такий самий ефект, як 1. Фізичні контакти діють незалежно від ваги. Ближній об'єкт збоку не приховує стіну попереду. Обхід — розширення базових правил без гарантії уникнення зіткнень.

Gather, Spread та Route додають тимчасові локальні цілі до тієї самої моделі агентів і можуть сповільнювати або зупиняти їх. Круг збору — м'який орієнтир щільності, а не тверда межа чи обов'язкова кругла форма. Для керованих команд локальна перевірка варіантів і обмежене трьома проходами узгодження враховують видимих сусідів і стіни до фіксації кроку. Вони враховують напрямлені політики взаємодії та є розширенням класичного Free Boids, а не повним планувальником. Перешкоди, шум, щільність, велика швидкість та обмежений огляд усе ще можуть спричиняти зіткнення і затори. Динаміки прискорення, гальмування, jerk, роторів і орієнтації корпуса у цій гілці немає; попередня модель збережена у `codex/copter-experiment`.

Вітер — кінематичний додаток до земної швидкості, а не аеродинамічна сила. Перекриті потоки додаються; сильний вітер може знести нерухомого агента. Шум — гаусова похибка положення для локальних спостережень. Фізичні контакти використовують істинні координати та перевірку дисків і прямокутників уздовж усього кроку. Загиблі лишаються маркерами й більше не перешкоджають іншим.

## CLI та аналіз

```powershell
cargo run --release --bin simulation -- --steps 400 --rectangle 4 0 2 3 --obstacle-angle 30 --rectangle 8 2 1 2 --obstacle-angle -15 --group -3 0 10 1 42 boids --gather 12 0 1 --group -3 5 8 1 99 boids --interaction 0 1 avoid --interaction 1 0 ignore --trace run-001.jsonl
```

`--rectangle` та `--square` повторюються; кут після фігури застосовується до неї. Параметри профілю й команди після `--group` діють до наступної групи. Параметри профілю успадковуються, команда очищається. `--empty` створює сцену без агентів. Без явних груп `--agents` залишає одногруповий CLI. Решта параметрів — у `--help`.

Одне середовище можна запускати з різними групами, наприклад: `cargo run --release --bin simulation -- --scene scene.swarm --group 0 0 10 2 42 boids --speed 2 --steps 200`. Прямокутники та поля, явно задані в CLI, додаються до завантаженого оточення.

Stdout містить JSON-підсумок. `--trace` створює новий JSONL із початковим і кінцевим станом та кожним N-м кроком згідно з `--trace-every`; наявні файли не перезаписуються. Події між записаними кадрами зберігаються. Для ідентифікації агентів та груп протягом запуску використовуйте `uid`. JSONL — журнал для аналізу, а не програвач записів.

### Перший експеримент

У PowerShell, з кореня проєкту:

```powershell
cargo build --release --bin simulation
cd analysis
python -m pip install -e .
python -m swarm_analysis run experiments/smoke.json --binary ../target/release/simulation.exe --output ../work/analysis/smoke --timeout 60
```

На інших системах шлях до виконуваного файлу зазвичай закінчується на `simulation` без `.exe`. Для кожної серії обирайте нову вихідну теку: наявна не перезаписується. Відкрийте `work/analysis/smoke/report.md` у корені проєкту. Звіт і графіки показують стани агентів, контакти, прибуття, швидкість, згуртованість і рух за маршрутом. Успішне виконання програми не означає автоматично, що задача виконана або зіткнень не було. Докладніше — у [посібнику аналізатора](analysis/README.md).

## Перевірка та обмеження

```powershell
cargo test --all-features --locked --offline
cargo clippy --all-targets --all-features --locked --offline -- -D warnings
cargo fmt --check
```

Тести охоплюють рух у SI, окремі правила Boids, відтворюваний seed, напрямлені політики груп, перешкоди, пресети, маршрути, шум/вітер, збір та JSON. Тести аналізатора запускаються командою `python -m unittest discover -s tests` із теки `analysis/` після встановлення залежностей.

Однаковий seed не гарантує побітової рівності між платформами. Штучного ліміту кількості агентів у вікні немає, однак щільні сцени та попарні перевірки початкового розміщення можуть бути дорогими; [старі вимірювання](docs/performance.uk.md) не визначають поточний FPS. Аналізатор підтримує статичні CLI-сценарії та має обмеження на попарні метрики. 3D і програвач записів ще не реалізовані; майбутні дослідження описано в [плані](docs/research-roadmap-2d-3d.md).
